## Layer 1

- **Unified “SlowBlock” metrics across clients**: proposed a cross-client execution metrics spec (with a linked draft spec) to make performance comparisons and protocol decisions more data-driven (e.g., repricing analysis, network health monitoring).

## Research

- **Staking decentralization & ops resilience**:
  - [Native DVT for Ethereum staking](https://ethresear.ch/): proposed protocol-enshrined DVT: allowing a single validator (with enough balance) to register multiple keys with an m-of-n threshold, aiming to reduce operational complexity vs. off-protocol DVT while improving security/decentralization properties.
- **Execution-layer scalability & worst-case behavior**:
  - [Worst-Case Block Size and Calldata Repricing for Glamsterdam](https://ethresear.ch/): analyzed a new worst-case block-size construction and discussed repricing directions (incl. access-list and calldata-floor repricing ideas) in the context of higher gas limits / blob counts and future PBS timelines.
- **Applications / UX bridging physical ↔ onchain**:
  - [Crypto Native Cash: Bridging physical Cash and DeFi](https://ethresear.ch/): proposed using ERC-4337-style account abstraction + NFC-bound “physical possession” keys and a multi-key governance model to approximate cash-like transfer UX while retaining onchain controls (e.g., freezing/recovery).

## Stuff for Developers

- [Foundry v1.6.0 (rc1)](https://github.com/foundry-rs/foundry/releases) (release candidate) shipped with Osaka as the default EVM hardfork, parallelized stateless fuzzing + configurable invariant check intervals (claiming up to 3.6× faster deep runs).
  - Experimental: a Rust rewrite of `foundryup` was introduced to improve install/upgrade UX over time.
- [Hardhat v3.1.5](https://github.com/nomicfoundation/hardhat/releases) included small but practical DX improvements: better Solidity test display, a bumped viem across packages, and new/updated Solidity build hooks.

## Security

- **Makina Finance exploit**: a flash-loan-driven price manipulation attack drained ~1,299 ETH (~$4M), with Decrypt reporting MEV dynamics where a builder frontran portions of the flow; reported root cause was classic oracle/spot-price manipulation around a liquidity pool.

## EIPs/Standards

- EIPs (Core, Networking, Interface):
  - [EIP-7892: Execution Layer Triggerable Withdrawals](https://eips.ethereum.org/EIPS/eip-7892): Status: Moved to Final — Specifies execution-layer–initiated withdrawals, completing the standard for validator withdrawal control.
  - [EIP-7910: Beacon Block Root in the EVM](https://eips.ethereum.org/EIPS/eip-7910): Status: Moved to Final — Exposes the beacon block root to the EVM, enabling native cross-layer verification.
  - [EIP-7934: Block-Level Access Lists (BALs)](https://eips.ethereum.org/EIPS/eip-7934): Status: Moved to Final — Finalizes block-level access lists, a key building block for ePBS and future block construction.
  - [EIP-7823: Execution Payload Bodies V2](https://eips.ethereum.org/EIPS/eip-7823): Status: Moved to Final — Defines a revised execution payload body format to support future PBS designs.
- ERCs (Application Layer):
  - [ERC-7935: Human-Readable Chain Names](https://eips.ethereum.org/EIPS/eip-7935): Status: Moved to Final — Standardizes human-readable chain identifiers for better UX and interoperability.
